Read this at spec time (S0), when you are deciding what the lesson must make the student able to do. Do not read it at build time; by then the decisions it governs are already made.

## Where CAET lessons sit

Almost every CAET day is **UNDERSTAND IT** with a **DO IT** tail: the student must hold a mental model (what resistance is, what the meter is doing) and then perform a bench action correctly (hook the meter up without destroying it).

That pairing is why the beat spine is what it is. It is not a house style. Each beat is a research finding wearing work clothes.

## The beat spine, and the effect each beat is exploiting

| Beat | The mechanism | Why it is there |
|---|---|---|
| Start | Advance organizer | Names the goal and the objectives before content, so the incoming material has somewhere to attach (activation). |
| Ticket | Problem-centered opening | A real bench fault gives the abstraction a reason to exist. Merrill's first principle: learning is promoted when it starts from a real problem. |
| Define | Pre-training principle | Vocabulary, symbol and unit land visually before anything else references them. Reduces extraneous load later. |
| Poke, with the prediction first | Generation and testing effect | The student commits to an answer before the object moves. Committing first is what makes the correction stick. A control that just responds teaches far less than one that first proves you wrong. |
| Walked number | Worked example effect | For a novice, watching one number carried all the way through beats solving unsupported problems. Admitting the rounding is part of the worked example, not an aside. |
| Photograph on the flip | Dual coding | A schematic teaches the symbol. Only a photograph teaches recognition of the physical part on a bench. Both channels, not one twice. |
| One poke per beat | Cognitive load theory | Two interactions on one idea compete for the same working memory and neither lands. This is the reason for the rule, not tidiness. |
| Checkpoint with retry | Retrieval practice | The check is a learning event, not a measurement. That is why every option gets a teaching sentence and why a miss earns another attempt. |
| Field card | Integration | Closes on the objectives in the student's own working terms, so the knowledge leaves the screen. |

## Merrill's five principles, mapped to this format

The kit does not carry the narrative-module Merrill document from the reference folder. That file maps a different format (cold open, crucible, pivot) and following it here produces the wrong lesson. This is the mapping for the Electric Ink spine.

1. **Problem-centered.** The Ticket beat. A real fault with real numbers, before any theory.
2. **Activation.** Start and Define. Objectives up front, vocabulary before it is used.
3. **Demonstration.** The walked number and the figures. The expert reasoning is visible, not just the result.
4. **Application.** The poke and the checkpoint. The student does the thing the beat is about.
5. **Integration.** The field card, and the shop story that says where this shows up on an aircraft.

If a beat map cannot say which of these five a beat serves, that beat is decoration. Cut it.

## The gap this format still has

Spacing. Every effect above is exploited inside a single lesson, but the spacing effect operates across days and weeks, and nothing in the current product does spaced review. The research is clear that a single training event without a retention plan loses most of the learning by day 30.

This is a product gap, not a lesson gap. Do not try to solve it inside one lesson file. It belongs in the course or the student hub, and it is worth raising with Nick when the library is further along.
